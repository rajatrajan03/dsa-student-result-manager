Bubble sort — O(n²)

Compares each neighboring pair and swaps them if out of order, one pass at a time, until nothing needs swapping. No built-in sort used.

Selection sort — O(n²)

Each pass scans the unsorted part for the minimum, then swaps it into place. Only one swap per pass — fewer swaps than bubble sort.

Insertion sort — O(n²)

Builds the sorted portion one student at a time, shifting larger values right to make room — the way you'd sort playing cards in your hand.

Merge sort — O(n log n)

Divide and conquer: splits the list in half recursively down to single students, then merges pairs back together in sorted order.

Linear search — O(n)

Checks every student one by one from the start until a name matches, or the list runs out. Works on unsorted data but doesn't scale well.

Binary search — O(log n)

Array is sorted ascending first (required for binary search), then the middle is checked and half the array is discarded each step — far fewer checks than scanning one by one.

Recent additions — queue (FIFO)

Newest student joins the back. Once more than 5 are tracked, the oldest one leaves from the front — first in, first out. (Undo, in the Overview toolbar, uses a Stack — LIFO — the opposite order.)

Grade distribution — HashMap frequency count

Every student's grade is tallied in a hash map keyed by letter grade — one pass, O(n).

Duplicate marks — HashSet

Checks whether any two students share the exact same marks, using a HashSet's O(1) membership check instead of comparing every pair.

Binary Search Tree — insert + inorder traversal

Each student is inserted keyed by marks: smaller goes left, larger goes right. Reading the tree inorder (left, node, right) visits every student in sorted order automatically.

Priority queue — who needs review next? (min-heap)

Every student sits in a binary heap keyed by marks, so the lowest score is always at the root — the one who most needs attention next. "Pop next" removes the root and sifts the heap back into shape (heapify-down), the same O(log n) operation a real priority queue uses.

Pair with target sum — "Two Sum" pattern

Finds two students whose marks add up to a target. Instead of comparing every pair (O(n²)), each student is checked against a hash map of everyone seen so far — O(n).

Reverse the list — two-pointer technique

One pointer starts at the front, one at the back. They swap their students and step toward the middle until they meet — O(n) time, no extra array.

Sliding window — best-average streak

Finds the run of k consecutive students (in current list order) with the highest combined average — the window slides one step at a time, adding one student and dropping another instead of re-summing from scratch. O(n).

Prefix sum — running average

Precomputes a running total so the class average "so far" at any point is a single lookup instead of re-adding from the start. See the trend on the Charts tab.

Recursion — sum of marks via call stack

Instead of a loop, the function calls itself on the rest of the list until it hits an empty list (the base case), then each call adds its student's marks as the stack unwinds.

Recursion lab — factorial via the call stack

factorial(n) calls factorial(n−1) until it hits the base case factorial(0)=1, then each call multiplies as it returns. Watch the call stack grow going down and unwind coming back up.

Pick a value from 0–10, then run it.

Hashing lab — how a hash map finds a bucket

Type any word. Its letters are added up into a number, then reduced with % 7 to pick one of 7 buckets — instant placement, no scanning. Two different words landing in the same bucket is a collision; the bucket just chains them together in a list.

Type a word and insert it to see which bucket it lands in.

Graph lab — BFS vs. DFS

A small fixed graph of 8 nodes. Breadth-First Search explores level by level using a Queue; Depth-First Search plunges down one path at a time using a Stack (or recursion). Run both from the same start node and compare the visiting order.

Every edge here also has a weight (shown on the line). Dijkstra's algorithm finds the cheapest path between two nodes — not just any path — by always expanding the closest unvisited node next.

Linked list lab — nodes and pointers

Unlike an array, a linked list doesn't sit in one contiguous block — each node just holds a value and a pointer to the next node. Inserting at the head is O(1) because nothing has to shift; reaching the tail (or any middle node) still costs O(n) because you have to follow the pointers one by one.

Empty list. Insert a value to begin.

Dynamic programming lab — memoized vs. plain recursion

Plain recursive Fibonacci recomputes the same values over and over — fib(30) makes over a million calls. Memoized (DP) Fibonacci stores each result the first time it's computed and reuses it — the classic trade of a little memory for a huge amount of time.

Trie tree lab — watch the tree grow as you type

A Trie stores words letter by letter, sharing branches for common prefixes. Insert a few words that share starting letters (e.g. "cat", "car", "cart") and watch how they branch off from a shared path instead of each getting a separate line.

Insert a word to start building the tree.

N-Queens lab — backtracking

Place queens one column at a time so none attack each other. Whenever a queen has nowhere safe to go, backtracking removes ("un-places") the previous queen and tries her in a different row — the core idea behind every backtracking algorithm.

LRU cache lab — HashMap + doubly linked list

A fixed-size cache: a HashMap gives instant O(1) lookup by key, while a doubly linked list keeps every key ordered by how recently it was used. Getting or putting a key moves it to the front. When the cache is full, whatever sits at the back — untouched the longest — gets evicted.

Cache is empty. Put a key/value to begin.

Topological sort lab — subject prerequisites

A directed graph of course prerequisites: an arrow from A to B means "A must be taken before B." Topological sort produces one valid order to take every course in, respecting every arrow — it only works because this graph has no cycles (a DAG).

Union-Find lab — detecting a cycle as edges are added

Each node starts in its own set. Union-Find merges the sets of an edge's two endpoints one edge at a time — if an edge's endpoints are already in the same set, adding it would create a cycle, so it's rejected instead. Path compression keeps future lookups fast.

Matrix lab — spiral traversal of a 2D array

A matrix is just an array of arrays. Spiral traversal visits every cell by shrinking the boundary inward — right along the top, down the right side, left along the bottom, up the left side, then repeat — a classic 2D-array walking pattern.

Circular queue & deque lab

A circular queue reuses freed slots by wrapping the "rear" pointer back to index 0 instead of growing forever — fixed-size, O(1) operations. A deque (double-ended queue) goes further, allowing insert/remove from both ends.

Fixed-size circular buffer (6 slots) — front/rear wrap around.

AVL tree lab — a self-balancing BST

A plain BST can degrade into a straight line (O(n) lookups) if values arrive in sorted order — try inserting 1,2,3,4,5 here and watch. An AVL tree fixes this automatically: after every insert, it checks each node's balance and rotates subtrees back into shape, guaranteeing O(log n) height.

Insert values — try 10, 20, 30 in order to see a rotation happen.

Counting sort lab — sorting without comparisons

Every sort on the Sorting tab compares pairs of elements. Counting sort never compares anything — it counts how many times each value appears, then rebuilds the array from those counts. It's O(n + k) where k is the value range, but only works well when k isn't much bigger than n.

Minimum spanning tree — Prim's vs. Kruskal's

Both find the cheapest set of edges that connects every node with no cycles — they just build it differently. Prim's grows one connected blob outward, always adding the cheapest edge leaving it. Kruskal's ignores connectivity and just sorts all edges cheapest-first, using Union-Find to skip any that would form a cycle.

Bellman-Ford & Floyd-Warshall

Bellman-Ford finds shortest paths from one source and — unlike Dijkstra — still works if some edge weights are negative, by relaxing every edge n−1 times. Floyd-Warshall finds the shortest path between every pair of nodes at once, by asking "does going through node k shorten this path?" for every possible k.

Huffman coding lab — compression via a greedy tree

Count how often each character appears, then greedily merge the two rarest characters/groups into a new node, over and over, until one tree remains. Reading left/right turns as 0/1 down to each leaf gives that character's code — frequent characters end up with short codes, rare ones with longer codes.

Bit manipulation lab

Numbers are just bits under the hood — these tricks work directly on them instead of treating them as decimal values, which is often much faster: counting set bits, checking powers of two, and swapping two values with no temporary variable.
